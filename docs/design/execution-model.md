# 执行模型

Core 提供语言无关的图结构与依赖；Block Compiler 生成 Workflow ABI v9 的普通工作流、Nodeset 与 Loop Block。Target 负责真实执行，Tooling 负责配置、质量检查与展示。

所有执行节点通过正常边激活下游。就绪队列提交独立分支；节点完成真实清理后交付输出；`join_policy: all` 消费本轮所有前驱的完成信号再执行。分发节点通过 `config.max_concurrency` 设置自身直接调用的容量，默认 8，任一调用实际退出后补位。串行关系由依赖链表达。

Python 的 plan、block、compiled 三种入口共用同一图调度器；JavaScript AOT 发射事件循环调度。锁保护与取消生命周期覆盖已启动节点至实际退出，错误保留清理信息。详细配置与迁移见[普通图并发与汇合](graph-concurrency.md)。


`global_state` 表示调用会影响进程内共享状态；它不会自动建立所有根图共用的全局串行队列。需要排他访问的工作应明确声明 `execution_lock`，并使用同一业务域的锁键。父作用域持锁时，子作用域不能换用不兼容的键；发生异常或取消也要先等真实执行和清理结束，再释放租约。

旧 `async`、`detached`、`result_key` 调度字段已撤销，隐藏目标必须改成普通节点与显式连接。工作流执行探针用于核对图、契约、分支和清理行为；它通过不等于证明业务结果正确性，业务断言仍需由项目提供。

## 命名入口与运行范围

`pipeline.entries` 选择起始 terminal 和该入口可达的调度路径，可覆盖公开输入输出；多个入口复用同一核心节点。审查和构建检查完整图，连任何入口都无法到达的孤立节点仍报错；各入口分别检查契约与汇合。源码运行只对所选入口及其实际引用的 Nodeset / Loop 定义做执行前图检查，未选入口的 planned 内容不会阻止已实现入口运行。模块装载、源码绑定和全图编译的原生错误仍会报告，不以入口选择跳过。

AOT 在构建时保存每个入口的范围和策略，运行时直接选择已准备计划，不重新编译或审图。Python 源码运行历史记录实际入口；HTML 首次打开该记录时默认显示此入口，用户可切换其他入口查看。

## 跨 workflow 的宿主责任

普通节点通过 Capability 和调用级策略使用 `self/call/wait/send/receive/kill`。call 等待新实例接入后返回身份，wait 等待真实终态；send 只等待本地交接，receive 无消息时等待。取消等待不自动停止对端，kill 由目标宿主确认停止或明确拒绝。命令包装进程退出不能代替实例终态。

本机 JSON 协议、邮箱和启动握手位于 `coordination/`，不承担业务调度。作者提供命令、环境、宿主和长期实例清理；没有运行组、自动子进程清理或隐式进程池。内部图分支的取消与清理仍由原执行器负责，与独立 workflow 的生命周期分开。端口 IO 也是普通 SDK 节点调用 Capability，不再有原生 IO 执行分支。接口与迁移见[用户手册](../../distribution/docs/user/workflow-coordination.md)。
