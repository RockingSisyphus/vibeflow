## PY-A02：Plugin 分支没使用已经生成的新真实调用事实，继续按 helper 名称猜效果

正式 CLI 同一 Plugin 对照：

```python
def write(value):
    return value

class Runtime:
    def before_node(self, node_id, node_type, inputs):
        write(1)
```

只将 `write` 定义及调用同时改名为 `identity`，其他声明、工厂、规则和函数体不变：`write` 版 FAIL，报 `NODE.EFFECT.CALL_FORBIDDEN: banned call in module helper: write`；`identity` 版 PASS。同一个纯 write helper 在 BaseLib 版 PASS。直接 Rule 另试 `read` 和纯 `Value.close()`，Plugin 拒绝，BaseLib/ordinary 接受。

真实链是 validate → selected lifecycle Plugin Rule → `no_side_effects(kind=plugin)` → 未接真实解析位置的 ModulePurityVisitor → 名称猜测。历史 `f169429 ModulePurityVisitor` 也是名称猜测；新系统已在其他分支替换为真实 source facts，这一分支未完成接入。它不同于 PY-A01 scanner 缺 AST 检查，是新资料未被旧遍历消费。

删除边界：Plugin 同样使用其当前闭包的解析调用事实，并保留 helper 实际函数体效果审查；不要增加 `write/read/close` allowlist，也不要去掉选中 Rule。
