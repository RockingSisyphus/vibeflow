## JS-M01 JavaScript effects/import Rule 的 policy 参数无效；import Rule 的 effect_scope 也无效

分类：新Rule包装仍固定调用历史判定算法，接受的有效参数未送达判定层；严重度：medium。

Core执行计划会显示override已选入params；JS source判定层不可能看到policy。no_side_effects的effect_scope有真实效果，但policy不读、不记录、不传送；import_side_effects不读任何params。

当前位置：
- [effects.py:7](/home/rockingsisyphus/projects/VibeFlow/src/vibeflow/builtin/effects.py:7)–18
- [builtin_plugin.py:21](/home/rockingsisyphus/projects/VibeFlow/src/vibeflow/targets/javascript/quality/builtin_plugin.py:21)–32
- [rule_session.py:248](/home/rockingsisyphus/projects/VibeFlow/src/vibeflow/targets/javascript/build/rule_session.py:248)–258

真实调用链：RulesetDescriptor relations $self overrides effects/imports → Core compile_ruleset参数schema验证与有效params计算 → _RuleSession.execute编译计划并解析catalog native_binding → javascript_rule_bindings.effects/imports → _source_check → _AnalysisCache.source_check -> run_rule_check_driver → toolchain_driver.mjs按ruleTopics执行固定算法.

历史：Rule迁移提交就通过topics包装既有source driver；目前只是移到标准plugin原生bindings，参数投影缺口仍与当时相同。

行为证据：使用当前正式catalog/Ruleset执行两个phase，`$self overrides`覆盖两条call。Core计划的`parameter_sources`为`override:$self`；每次真实Node/TS driver请求均不含policy。以下为同一个含`console.log`的Node：

| 覆盖参数 | Core调用params | effects topics | imports topics | 结果 |
|---|---|---|---|---|
| none + {} | 原样记录 | module_state, host_io | purity, imports, ownership | VF_BASE_LIB_HOST_IO |
| none + audit_marker | 原样记录marker | module_state, host_io | purity, imports, ownership | VF_BASE_LIB_HOST_IO |
| terminal + {} | 原样记录 | module_state | purity, imports, ownership | 无finding |

因此effects的scope通道生效，policy通道完全缺失；imports的全部params均未读取。marker只证明丢参，不替未定义的JS policy子键指定语义。

完整行为证据：[vibeflow-wide-js-formal-policy.json](/tmp/vibeflow-wide-js-formal-policy.json)。

## JS-M02 ownership topic 仍从正式import Rule发出，但driver已不消费；effectScope仍被正规化后无人读取

分类：已删除的历史source-owner判定仍留有请求和无消费者字段；严重度：low。

请求名与实际执行能力脱节，遗留字段没有可观察作用；容易让维护者误以为ownership审查或owner级effectScope仍生效。

当前位置：
- [builtin_plugin.py:31](/home/rockingsisyphus/projects/VibeFlow/src/vibeflow/targets/javascript/quality/builtin_plugin.py:31)–32
- [toolchain_driver.mjs:283](/home/rockingsisyphus/projects/VibeFlow/src/vibeflow/targets/javascript/resources/toolchain_driver.mjs:283)–297
- [toolchain_driver.mjs:2222](/home/rockingsisyphus/projects/VibeFlow/src/vibeflow/targets/javascript/resources/toolchain_driver.mjs:2222)–2241
- [project_resources.py:363](/home/rockingsisyphus/projects/VibeFlow/src/vibeflow/targets/javascript/build/project_resources.py:363)–365

真实调用链：正式import_side_effects -> _source_check topics purity/imports/ownership → run_rule_check_driver -> toolchain_driver rule_check → driver只dispatch imports/purity/completion/module_state/host_io；ownership忽略 → target_neutral_import_policy owner不产effect_scope -> normalizeImportPolicy仍补effectScope -> 没有reader.

历史：0.15.2 ownership topic执行auditUnclassifiedHiddenWork，且只服务owner.kind=source。当前worktree删掉该函数/dispatch与历史source-owner分支，调用方topic与effectScope正规化残留。effectScope从Rule迁移时即无实际reader。

行为证据：直接真实driver给同一`setTimeout`/`Promise.resolve`源码传`ownership`，返回空；传`completion`报告`VF_NODE_LONG_LIVED_LISTENER`和`VF_COMPLETION_IMMEDIATE_PROMISE`。正式import Rule还发送ownership。旧0.15.2的`auditUnclassifiedHiddenWork`只针对`owner.kind=source`；当前已删函数及dispatch，当前正式owner生成器也不生成旧source kind。

`effectScope`当前只在normalizeImportPolicy生成，全源码无reader，正式owner生成也没有effect_scope字段。它自Rule迁移时就未接入判定。不能据此宣称completion漏检，亦不能把复用中的driver整体删掉。

完整行为证据：[vibeflow-wide-js-probe.json](/tmp/vibeflow-wide-js-probe.json)。

## 已退役与排除项

- **JS-X01 历史WorkflowSpec解析器/模型/validator和双路builder**（retired_in_current_worktree）：当前上述旧文件删除，target公开API不再export旧模型/parse API；build/emitter均强制canonical WorkflowPlan+JavascriptBindingPlan。Bound*View只读投影没有独立parser。
- **JS-X02 历史JavaScript独立PluginDescriptor解析与policy Plugin hooks**（retired_in_current_worktree）：现有plugin_descriptors.py只做JavaScript selection/binding并使用Core descriptor解析；旧policy类型/extendPolicy等hooks明确拒绝，compiler lifecycle不得返回findings/relaxations。SDK、worker、runtime、d.ts均ABI v3。
- **JS-X03 历史quality/models.py+validation.py与nodeset_limits.py**（retired_in_current_worktree）：当前这些文件删除；正式Application执行Rules，Target quality/source只提取facts。
- **JS-X04 project javascript.host_extensions与workflow host_extensions两来源fallback**（retired_in_current_worktree）：当前共用项目配置解析器拒绝旧字段。Application host选择走workflow同一入口，S02修复当前worktree已落地。
- **JS-X05 quality/source.py无产品静态入边**（public_facts_facade）：公开facts collector façade，独立测试明确验证其不assemble默认Rules；不是旧quality validator残留。冻结parity cases的旧分支只在旧包baseline中执行。
- **JS-X06 toolchain纯度/IO/module state/completion算法沿用与原生Rule binding**（legitimate_algorithm_reuse）：算法仍在同一正式Rule选择的topic下执行；catalog native_binding按贡献来源解析，并非builtin ID专属绕过旧注册表。不能仅因函数历史早就存在判为旧系统耦合。
- **JS-X07 TS程序构建的classic/native API分支**（backend_api_adapter）：首个JS AOT提交19a26c8已同时适配API并要求TS>=7<8；现有TS7.0.2缺classic createProgram/createSourceFile。分支不是TypeScript5→7迁移遗留证据。
- **JS-X08 legacy node.async与PipelineInputSpec.required=None**（single_contract_and_explicit_target_limit）：JS无独立node.async parser，Core单一parse_node_async投影schedule后以Target facts覆盖event_loop executor；正式build required=None明确VF_AOT_INPUT_REQUIRED。result_key实跑prepare转成deferred/event_loop；不能把共享源配置保留当两套异步engine。
