# 1.5.0 本地验收记录

本轮只交付本地源码与 collaborative / autonomous 分发包，另外验证 wheel 隔离安装；不推送、不发布、不修改外部项目或已部署服务。Workflow ABI v12、Plugin ABI v5、AOT v6、预览快照 v5；Rule ABI v3、HTTP 协议及启动清单 v2 不变。

固定的 `context.workflow` 方法保留协作、实例身份、取消与实际清理。`workflow_operations` 描述操作事实，供调用描述、启动清单与预览使用；planned 调用只供展示。通用宿主注册、授权与注入式端口机制及专属辅助设施删除。应用使用普通模块或运行输入管理 DOM、监听和队列。

## 接口与行为

- 删除双语言 SDK 中的通用宿主接口、描述与资源目录、解析和授权规则、公共计划、运行时包装、构建与序列化，以及框架端口模板和相应配置、提示词、示例说明。
- Node 固定使用 `context.workflow.self()`、`invoke_sync(request)`、`call(request)`、`wait(request)`、`send(request)`、`receive(request)`、`kill(request)`。`self()` 始终可用；其余方法在实际调用时报告未连接或宿主不支持。Python 使用方法调用。
- 宿主参数为 Python `workflow_session`、JS `workflowSession`。会话只提供专用协作；每个 Node 绑定自身取消信号，Nodeset / Loop 共享根身份，新 workflow 使用独立身份。取消等待不停止对端，Kill 等待真实清理，业务及清理错误可观察。
- 固定 `workflow_operations` 只描述六种协作操作，Call 的展示用 `wait` 默认 false。已实现节点以定义为准；未定义 planned 调用可在调用处声明。目标、启动方式和预期对象仍使用既有 config 字段，planned 调用不进入实际启动清单。
- 浏览器直接使用 DOM，应用模块管理事件、队列和监听；同进程活对象通过普通运行输入传递，不写入配置或 AOT。持续 Loop 使用 `max_iterations: null`，省略仍默认 1000 次。

## 定向场景

- Python：源码和移除源工程后的 AOT，分别覆盖 plan / block / compiled 三种执行方式的独立 workflow 调用、同步子调用、消息、停止与错误公式对照。
- JavaScript：同一独立 AOT 在 Node 和真实 Chromium 中执行，验证计算结果、消息、实例隔离、取消与清理。
- 浏览器 DOM：导入后尚未监听；实际页面点击产生结果，两个页面独立运行，正常完成和停止均移除监听。
- 应用输入：并发存储请求、队列接收、计算和输出；持续 Loop 完成 1005 次处理后仍能停止并关闭。
- 源工程移除后的 Python AOT 可接受普通运行输入中的活对象，三种执行方式保留同一对象引用。

这些场景的定向通过不代替完整门禁；下面按固定代码批次分别记录。
