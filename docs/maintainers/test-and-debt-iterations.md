# 测试提效与技术债迭代

## 目标与基线

用户于 2026-10-21 授权无人监督期间自主推进普通修复；会导致项目结构大变的决定先留档暂缓。开始提交为 `155ec87`，此前修复已完成 18/18 完整门禁；默认测试并发随后改为 12，并经 44 项定向验证。版本号、正式 dist、远端分支和 Release 不在本任务范围。

基线证据为仓库旁 `VibeFlow-evidence/technical-debt-20261021/full-2-*`：完整门禁 1480.4 秒，其中规则回归 757.9 秒；JS 集成 170.3 秒、pytest 149.2 秒、Python 沙盒 105.7 秒、适配回归 88.8 秒。规则资源的 display/edits 两组内部串行形成长尾，调高最大 worker 数不能单独消除这一问题。

## 实施与每轮提交

1. **测试调度与断言整理。** 将可独立的 display/edits 工作按资源类别分配到同一个有上限的队列，保持每个修改—验证—恢复案例内部顺序。保留案例身份、正反控制与真实浏览器，不以跳过昂贵用例换取提速。检查过时的发射源码字节摘要断言，保留公开接口、计划及真实执行的独立保护。定向验证后单独提交。
2. **覆盖与技术债审查。** 按 Core/Block Compiler、两端 Target、Coordination、Tooling/展示、发行/文档、测试夹具逐项检查真实调用链。删除证实无调用且无公开契约用途的旧路径，收拢已分离职责，更新当前文档；历史基线、迁移诊断与有效可选 SVG 覆盖不因名称含旧接口就删除。针对发现的真实行为缺口补充回归，完成定向验证后提交。
3. **集成验收与复核。** 使用默认 12 workers 运行正式完整门禁，与基线分别比较各阶段耗时、案例删增依据和观察数量。保留所有失败批次，集中修复并定向复验后进行必要的完整复验。验收、文档与清理完成后提交收尾；尚需用户决定的结构性事项列出证据、方案及影响。

不以一定要删掉多少测试、增加多少模块或达到未经实测的秒数为完成标准。完成标准是：已审查范围的可自主修复问题闭环，覆盖删增有具体依据，实际效率已测量，必要门禁通过，每轮提交可追溯，结构性待决事项明确。

## 执行中的成本、目标与路线复核

主要成本是资源展示中的真实编译/浏览器运行及完整回归；先依据已有逐阶段耗时处理长尾，不增加另一套测试资格、锁或复杂调度框架。关键假设是：资源类别之间的项目和进程状态独立；旧源码字节快照没有额外业务语义；已有 Architecture/规则入口足以支撑新增覆盖，不需要大改产品结构。

在首个拆分资源批次、删改断言后的行为验证、技术债调用链审查完成，以及最终完整门禁后，复用实测证据复核剩余工作、验证代价、维护负担和假设。若实践推翻假设，按 critical-fork 重新判断；常规等价实现自主处理。用户休息期间，确需改变产品结构的选项先做低成本核查并留档，写清同一场景下各路线结果、机制、代价和未知；只暂缓依赖该决定的工作，继续独立任务。恢复讨论后更新本计划和验收依据。

实际使用目标模式，整项目标与必要验收完成后按 codex-task-alert 发送一次完成提醒。确需用户介入的事项先在聊天完整说明，再按其资格规则提醒；普通失败和进度不提醒，不用通知代替诊断。

## 迭代记录

实施中在此记录实际删增、验证、提交与待决项；原始报告在仓库外保存。

### 第一轮：调度与过时断言

- display/edits 分别按四种资源及额外案例拆分，总队列由 11 项变为 19 项；只使用外层有上限的队列，删除旧环境变量分派及备用嵌套线程池。每个案例仍在独立子进程中通过真实 CLI/浏览器观察，修改与恢复序列不拆开。
- 退役 JavaScript emitter 的 9 份完整源码字节摘要：上一轮仅修剪 helper 文件末尾空行就必须更新，不能独立证明用户语义。保留声明、公共计划、导出接口及真实执行测试。
- 删除 `deferred` 发射案例：迁移成普通 SDK 异步节点后，它与 `async` 的完整计划、声明和源码均完全相同。保留 async 覆盖；原 detached 案例改称 suspending_no_output，继续验证无业务输出的异步执行。
- 实测：定向测试 27 项通过；规则一致性 1,210/1,210，补充规则 680/680，无进程错误。案例 ID 完全相同，预期值仅 16 例的临时工作根路径不同，归一化该根路径后全部相同。
- 同一次本机运行中，规则一致性耗时 106.2 秒、补充规则 289.2 秒，合计 395.4 秒；此前同阶段 757.9 秒，下降约 47.8%。这反映任务拆分与默认 12 workers 的合并效果，不当作两者独立因果倍率；完整门禁总耗时尚待最终实测。证据在 `VibeFlow-evidence/test-debt-iterations-20261021/round1-*`。

### 第二轮：主展示覆盖与职责清理

审查覆盖 Core/Block Compiler、两端 Target、Coordination、Tooling/展示、发行文档与测试夹具。依据是实际导入方、声明导出、规则绑定、命令调用链及已有验收，不依据文件名或行数批量删改。

| 范围 | 结论与处理 |
| --- | --- |
| Core、Block Compiler、公共声明 | 未发现仍执行的原生 IO 专属分支；移除无调用的 schema `_provider_keys` 与编译/解析/Architecture 等模块的无用导入。共享计划、普通执行器和旧配置迁移诊断继续保留。 |
| Python Target | 规则直接从策略所有者取得 source_policy，移除 helpers 转出口；保留节点源码/模块副作用的不同分析职责。协议模块只保留实际语言接口与公开 effect-scope 桥，不保留无消费者的 flow 常量转出口。 |
| JavaScript Target、共享规则 | 两端内置规则装配直接使用共享 Capability handler；图审查直接使用共享算法，删除 Target 实现文件中的无用转出口及各层残余导入。SDK 导出、atexit 注册回调和 Target 自有规则声明仍有实际用途，保留。 |
| Tooling、Coordination | Host Extension 解析由使用者直接引用实际所有者；索引、快照、安装及 Target 采集的既有边界继续沿用。Coordination 的启动握手、实例状态、邮箱与 Target 接入分工仍有效，没有新增生命周期托管或平行执行器。 |
| 展示与测试 | 原资源矩阵只验收可选 SVG，补为同一浏览器进程验收离线快照四种主要视图；覆盖所有公开形状、有效颜色、文字、图标、覆盖与状态，样式修改/恢复也同时检查 HTML。保留 SVG 对照覆盖。新增 4 个真实 Python/JS SDK 与 CLI 案例，先确认合法多入口通过，再确认孤立 terminal/process 在 validate/build 均被准确拒绝；已有离线入口切换测试增加索引重建后继续识别入口的检验。 |
| 目录、当前文档、历史资料 | 具体 Target/Tooling 的项目规则选择测试移到 integration，共享图规则的入口健康测试移到 targets/shared。两份已完成且仍被发行记录引用的 AOT/展示实施记录移到 maintainers/history，更新所有入链与相对出链；保持当时 ABI、成绩和失败原文。当前用户文档和发行提示词已使用 ABI v9、普通端口与 HTML 快照审核，没有据旧关键词误删有效迁移说明。 |

保留边界：历史规则基线中的 IoSpec 只由 baseline 分支使用；`flow_kind: io` 和 `vibeflow.io` Ruleset 仍合法；可选 SVG 仍是产品接口；公共模块的显式 SDK/模型导出并非死代码。没有发现必须改变项目结构才能处理的待决事项；不宣称整个项目绝无未来技术债。

纵向验证的四类真实资源均通过 HTML/SVG 样式检查；另外 12 个状态/非法样式/失败审查案例及修改—恢复序列符合预期。首批定向运行暴露并保留了整理导入时丢失相对点的错误；随后新增跨 Target 测试暴露测试读取诊断层级不对（Python build 的既有公开结果将 HealthReport 放在 error JSON 字符串中）。分别修正导入和测试读取，未修改产品输出契约。最终定向复验与完整门禁结果见后续记录。

复核：新主展示覆盖复用每次 review 已生成的快照和已有浏览器，没有新增构建/依赖安装通道；浏览器增加本地视图加载，有实际额外成本，最终总耗时需由完整门禁决定。独立图元的形状与颜色均有真实 SDK 纵向证据，尚需矩阵全形状及发行隔离验证；没有证据要求大改既有执行机制。

第二轮最终定向记录：修正后 6 项入口/共享图规则测试通过；上一批其余 96 项（含项目规则、策略缓存、源码检查与真实离线入口/展开/重建索引）通过。另有四类 SDK 资源纵向 HTML/SVG 检查、12 项状态等案例指标及一个样式修改—恢复序列通过。仓库质检 0 error / 0 warning / 0 info，清理目标 0。原始失败与复验分别保留在 `VibeFlow-evidence/test-debt-iterations-20261021/round2-*`。下一步冻结实现，使用不传 workers 的正式完整门禁验证默认 12 并发、全形状矩阵与隔离发行。

### 第三轮：完整批次暴露的观察器职责混用

第二轮之后首次完整批次（`full-final-1-*`）跑完 18 项，17 项通过，耗时 1198.4 秒。唯一失败为 Python 审查性能的 entry-review 观察错误：该批次复用了原 resource_browser 的 SVG 观察接口；新增资源 HTML 参数后，此处仍只提供 SVG 参数。pytest 4672、Python 沙箱 103、JS 集成 50（零跳过）、规则 1210/680、适配 207、真实展示、wheel 与双 profile 均通过；不把这一批记成完整通过。

根因是公共 SVG 观察工具放在资源专项目录且承担了资源页面职责。本轮把通用 SVG 观察器放到 fixtures/support，性能测试直接调用它；资源专项只负责自己的四类 HTML 视图，并复用公共观察器已启动的浏览器。资源观察器明确要求快照参数，不按参数缺失静默降为 SVG。Python 性能入口同时保留浏览器失败的 stdout/stderr，避免再次只得到 CalledProcessError 代码。没有新增第二套浏览器启动或产品兼容路径。

复核：此次失败要求修正测试辅助工具的边界，不要求改变产品结构、验收目标或放宽条件。首批新增 HTML 指标在完整矩阵中全部通过，83 个既有案例增加主展示断言。规则阶段 414.9 秒，较基线 757.9 秒减少约 45.3%，包含新增 HTML 的成本及并发配置变化；不将该失败批次的总时长作为最终通过成绩。先定向验证 SVG 性能与资源 HTML 两种调用，再提交并复验正式完整门禁。

第三轮定向复验：代表性性能批次 16 项全部匹配，observation_errors 为空；真实资源 HTML/SVG 观察也通过，页面错误和联网请求均为空；仓库质检零错误、零警告。证据为 `round3-*`。修正只涉及测试观察器职责与失败诊断，下一批继续使用默认 12 workers 完整门禁。

最终复核：本轮可自主修复的确认问题已闭环，实际效率与覆盖删增有证据，所有必要完整验收通过，每轮实现均已独立提交。没有必须请用户裁决的结构性待办。历史基线、迁移诊断、公开导出与可选 SVG 的保留有实际用途，不能据旧名称再删一次；本结论不表示项目不存在未来可发现的技术债。后续普通优化仍以真实长尾和独立行为价值为依据，不按删测数量或文件行数继续拆分。
