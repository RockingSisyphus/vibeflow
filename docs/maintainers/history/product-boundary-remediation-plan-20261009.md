## 执行中的成本、目标与路线复核

必须结合实践证据分析剩余实现工作量、验证代价、维护负担和替代路线迁移成本；目标及关键假设不能因计划已批准就免于复核。不凭空估计精确工时。执行中的判断、中文解释、商讨和暂停沿用 critical-fork；确需用户介入时先形成完整说明，再按 codex-task-alert 发送一次提醒。只暂停依赖决定的工作，继续保留选项的独立部分。决定后更新本计划、验收及必要决策记录。

关键假设及复核节点：

- 移除未知方法名猜测后，可以同时退役 ExitStack 补偿，不损害明确 I/O 和运行时 cleanup：第一批正常对象/真实外部操作对照、效果规则定向验证后复核。
- 有限输入别名不需要恢复异常、闭包、参数污染模型：首个通过正式 Rule/CLI 的有限输入原型后，以及出现连续特殊补偿前复核。
- Rule 拆分可复用同一 SourceContext，不需要第二套事实服务或默认 Core 门禁：首个独立 Rule/空 Ruleset 案例后复核。
- runtime_dispatch 是推断展示事实，不参与真实调度和锁：删除消费者前及新计划真实执行后复核。
- 无 lock 项目可通过实际工具解析完成构建和 publish：首个真实无 lock 构建/publish 后复核；必要版本兼容保留。
- 格式一次迁移的成本主要是生成资料和测试基线更新：消费者搜索完成、首个新 ABI/AOT 产物后及路线定型前复核。

若成本明显偏离已有依据，或小幅调整目标能改善效率、维护或用户价值，先低成本查证；按 critical-fork 判断自主处理、阶段讨论或必须询问。需决策时给出原目标、证据与未知、造成差异的机制、同一例子各路线的结果/代价，再问目标取舍并及时提醒。可保留选项记录具体讨论节点，最迟相关路线定型前讨论。
