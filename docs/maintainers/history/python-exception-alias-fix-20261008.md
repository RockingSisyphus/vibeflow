# Python 异常出口中的输入别名修复

本记录跟进[别名事实修复独立审核](python-alias-facts-review-20261008.md)中的 F05。原 F03/F04 的具体案例已修复，但 after-source-03 丢失了表达式中途抛错时的输入别名，不能据此前的完整验收认定本轮没有回归。原审核、原脚本、历史期待及上一轮验收证据保持原样。

## 结果目标与根因

`((alias := inputs), params['missing'], (alias := {}))` 先将 alias 指向实际输入；查询抛出 KeyError 时，最后的清除尚未执行。except 中直接 `alias.pop(...)` 或调用 `sink(alias)` 都应报告输入突变。若先清除再查询，异常分支使用的是新字典，应继续允许。global_state 不取消输入不可突变合同。

修前冻结全部 334 个产品文件，与上一轮 after-source-03 一致。原静态16项及正式 CLI16项分别有12项漏检；其中6个 helper 案例是新回归，6个 direct 案例是既有遗漏。它们属于同一表达式异常状态缺失的根因，详见[修前结果](../evidence/index.md#artifact-5b3507f2774e30c7)。

## 实现与保留边界

统一输入采集器在属性／下标查询、调用与其他已分析操作的求值时点记录异常出口，交给最近的 try。正常结束、未匹配异常、handler／else 抛出的异常分开经过 finally，再传递给外层。函数定义的默认值仍在外层求值；仅静态检查函数体，不会把其中的异常当成定义时发生。

所有状态沿实际声明归属投影。可能指向输入的值取并集；名称已绑定和精确字典证明取交集。参数的输入身份与字典证明沿 SourceContext 的真实调用及函数 AST 传播；params 的字典种子来自 canonical Node runtime，其他参数不因名字叫 params 就获得证明。只对实际证明未被遮蔽的 builtin Exception／BaseException 消除相应已处理异常；未知对象的查询及调用仍保留保守出口。

每个选定的最外函数 AST 采集一次其嵌套调用，避免把丢失外层状态的重复遍历伪装成新实参来路。闭包实际调用可能发生在定义之后：若同一声明存在可能的非字典写入，不将定义时的字典值作为捕获值的稳定证明；该事实按声明归属收敛，不影响调用者当前路径的字典值，也不污染 sibling 的同名局部变量。

透明控制块中的函数加入现有 SourceContext 调用索引，不引入第二套按名称猜测 callee 的解析。真实函数定义、参数、赋值、循环目标及导入建立绑定；删除及异常变量退出时的隐式删除取消绑定。推导式的所有目标属于其局部声明，但只有已执行的目标赋值才建立可用值。生成器创建只求值外层 iterable；直接交给已证明的 builtin 消费函数时，才把延迟函数体的状态应用到当前路径。

本轮不新增资源权限，也不取消此前的局部来源标记、清除能力或函数写回判断。没有引入完整 Python 运行时解释器、动态反射分析、通用生成器消费者分析或 callee 确定清除摘要。此前 clear3 的一项既有保守误报与 raw36 的四项普通未知 write 期待差异继续单列，不能改写为原期待全部匹配。
