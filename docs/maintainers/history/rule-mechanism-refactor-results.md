## 实现

Core 的 `rules/selection/static`、`dynamic` 和公共解析层统一缺省、替代、空列表与来源。`planning.py` 根据实际调用路径生成负责范围与接管边界，既有 `graph.py` 和 `execution.py` 承担组合、Records、执行和命令内复用。Workflow 静态默认使用既有 Ruleset 资源的 `workflow_default` 标记。

两个 Target 提供局部源码视图和图事实。Node 公开资料按实现、继承方法及实际 helper 切片；图规则区分当前图、命令背景、负责范围与显式边界。内置 Workflow 使用同一整体范围的分析、检查与汇总计划。首次加载、运行政策和 Architecture 保留当前调用的有效选择及完整路径。

删除旧默认注入、旧定义审查缓存和隐藏递归处理入口；Schema、SDK、示例、测试及发行手册一并迁移。JavaScript Rule ABI 为 `vibeflow.rule.v2`，外部插件迁移说明见 [用户迁移手册](../../../distribution/docs/user/rule-system-migration.md)。

| 已确认行为 | 实际实现与验证 |

| 本层与整体检查不重叠 | `current_graph` 使用有限子图调用；`effective_subtree` 在入口处理负责图，遇到显式选择停止内部遍历 |

| 同范围 Records 协作 | 内置 Workflow 的分析、六个检查主题和汇总使用显式依赖；混合范围报组合错误 |
| 复用与诊断归属 | 参数、源码、Records、范围和实现影响复用；完整路径、选择来源、替代项与全部受影响位置保留 |
| 空选择保留原生错误 | 解析、绑定和编译独立于规则选择；未调用声明与首次加载均有实际验证 |
