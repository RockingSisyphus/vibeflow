# 架构质检的阻断边界

## 2026-10-09 用户明确的职责边界

VibeFlow 是代码质量限制器与代码架构限制器，关注 Node 之间的关系及 Node 内的代码质量；不负责证明业务代码正确性或代码安全性。AST／符号分析可服务于实际资源、接口、依赖和质量事实，不以穷尽业务语言执行语义为目标。框架自身的配置、调度、绑定和接口处理仍须正确。

“选中了质量规则”不自动授权通用异常路径、跨函数污染、返回值、安全绕过或确定性证明。原有规则行为及历史 parity 是历史事实，不是无限延伸检查的产品承诺。具体收缩和退役建议见[职责边界审核](product-boundary-audit-20261009.md)；整改实施与验收记录见[执行计划](product-boundary-remediation-plan-20261009.md)；历史审核保留当时的事实，当前行为以活动代码、Rule 选择及新验收记录为准。

开发整改和后续审核使用[职责边界与整改规格](product-boundary-refactor-spec-20261009.md)，其中逐项列出源码入口、消费者、当前与目标逻辑、修改停止点及验收。该规格区分用户已确认定位与实施建议，历史记录仍保留原始事实。

## 既有机制与范围记录

用户项目审查由 Rule/Ruleset 统一执行。表中约束只有被当前对象的 Ruleset 选中才生效；`flow_kind`、external 或历史质检报告不另授予权限。规则结果只证明所选检查的结论，不代表工作流已经运行成功。

| 检查阻止的动作 | 用户要求或必要边界 | 不检查的实际损害 | 四项准入条件 | 处置 |
|---|---|---|---|---|
| `quality-check` 以错误状态退出 | 用户明确要求架构质检的 `FAIL` 和退出码 1 | 检查命令无法如实报告超限；执行构建时不会读取其历史结果 | 这是测量命令本身的结果，不是其他命令的运行准入；直接、局部且无资格状态 | 保留错误结果；警告只给 `CONCERNS` 和退出码 0 |
| `validate`、`review`、`build` 拒绝当前图的 nodeset 深度超限及当前已注册实现的硬规则违规 | 用户明确要求这些直接处理对象遵守已有图／实现规则 | 图或实现可在违反明确架构约束时被接受，后续执行不会自然指出该约束 | ① 用户要求；② 当前输入；③ 违反明确约束且自然执行不会报告；④ 复用局部 Core 规则。四项满足 | 保留原有命令作用范围；通过选中 Ruleset 的参数与覆盖决定限制；宽度默认仍为警告 |
| 非法 `runtime.nodeset_max_depth`／`javascript.nodeset_max_depth` 或质量策略字段使当前配置解析失败 | 当前命令必须获得确定的正整数限制和可用策略 | 布尔、零或非整数会令比较失去定义；下游普通错误不能准确指出字段 | ① 输入 schema 必需；② 当前字段；③ 否则无法可靠比较并定位字段；④ 局部解析。四项满足 | 保留 schema 校验，报告具体字段；数值作为内置 Rule 的默认参数，显式调用及覆盖优先 |
| 在 `build`／`run`／`validate`／`review` 前扫描所有未注册源码或读取既往质检报告 | 没有用户要求这些命令做项目级预检 | 不检查不会妨碍这些命令处理其直接输入 | ①②③不满足；还会扩大作用范围 | 不加入；`quality-check` 保留既有范围，领域规则不因此获得孤立源码覆盖承诺 |
| SHA、manifest、receipt、全量 dry-run、预测性资源与跨配置锁 | 没有当前动作所需的外部边界 | 不检查时由实际操作返回真实错误 | ①②③不满足；可能引入第二套控制面 | 不加入 |

验证证据分别记录为 Core／语言事实测试、隔离 CLI 沙箱和真实项目只读质检；这些证据不替代工作流真实执行。
