## 验证与执行复核

定向检查先覆盖两端事实、SVG、原生浏览器、默认命令、运行与发行适配，再运行完整门禁。新增浏览器断言用实际 SVG 形状的填充几何验证全部 14 种原生轮廓的多方向连接点，保留既有拖拽、展开、缩放、历史及离线验收；SVG 角色检查包含同端点、不同条件与调度/传递标记。

第一轮定向批次保留 28 失败、582 通过和 2 收集错误，暴露移除再导出后尚未迁移的调用，以及测试夹具缺失的真实字段。集中修复后再复验；不通过恢复转接壳解决导入问题，也不改写原批次结果。

本轮复核确认：原生边界可从同一轮廓生成浏览器 Path2D，不需要维护第二套形状交点公式；默认事实链路不需要 SVG，数据沙盒无需渲染器。主要成本为消费者迁移与两端/发行回归；删除桥接层使长期维护入口减少，保留历史用途的输入不额外迁移。第一轮完整批次 18 步均执行，13 步通过、5 步未通过：pytest 4,605 通过／4 失败；补充场景 597／680 匹配（83 处不匹配集中在资源展示与连续修改）；布局 1／4、Python 资源区 12／14，以及 Python 性能专项的一次浏览器观察未通过。原因为共享 MJS 移动后两处验收脚本仍引用旧路径，和测试将 Architecture 规范形状与 Mermaid 方言混用。修正实际消费者及分开的预期，不恢复旧路径、不跳过浏览器、不放宽几何和样式断言。原批次日志与机器报告完整保留。

较大真实输入重新生成耗时约 36.70 秒，快照 1,068,944 字节，首次显示约 195 ms；用一次布局绘制全部 666 个调用和 657 条边约 194 ms。此全展开测量直接设置展示状态，不能与此前逐个右键展开的总耗时作同一操作比较。无页面错误和联网请求。

修正后的定向复验：pytest 560 项通过，资源展示 103／103、连续修改 47／47 全部匹配，真实浏览器布局、两端资源区和代表性性能场景通过。此后冻结源码和测试，另开最终完整批次；第一轮结果单独保留，不能由定向结果改称完整通过。证据在仓库旁的 `VibeFlow-evidence/debt-cleanup-20261019`，较大的原始机器报告压缩保存，不保留依赖、候选发行包或一次运行的源码副本。
