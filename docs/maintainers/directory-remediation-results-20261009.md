# 目录整改结果

用户确认沙盒继续直接加载工作区 src。目录整理完成，产品核心未修改。

## 已落实

- 用户文档的唯一原稿在 distribution/docs；构建后的 kernel/docs 布局保持一致。
- docs 保存开发说明、当前设计、history 中的历史结论及证据索引。
- sandbox 仅按 Python / JavaScript 分组，保留真实 SDK、CLI、工作流和宿主案例；内部回归项目移至 tests/fixtures，原覆盖继续执行。
- dist 保留原 0.15.2 的两个正式目录、两个 ZIP 和校验清单；archive 保留历史发布物。正式 ZIP 与目录逐文件一致，原 SHA-256 校验通过。
- 构建器把新 ZIP 与发行目录一起发布；被替换的 ZIP 转入 archive，同版本不同构建也保留原件，失败恢复旧产物。候选目录默认在其旁生成 ZIP；不能只替换正式 ZIP 而让正式目录仍是旧版。
- 质检补充目录职责检查，正常 PDF、文本等开发文档仍可保留。测试的依赖缓存、worker 输出和 pytest 临时目录归入同一仓库外工作区，结束后统一清理。

## 成本、目标与路线复核

实际主要开销是完整运行，规则与资源组约 12 分钟；文件迁移和路径调整较快。剩余修正只影响文档读取、索引、仓库质检和发行路径约束，故复验这些范围及完整 pytest，并以原始快照证明其他验收输入没有变化。这样保留原测试覆盖与真实执行证据，减少无关的重复浏览器运行。

没有出现需要改变产品目标的新分叉。用户选择的源码沙盒方式已保留；测试基线作为运行输入继续在仓库中维护，历史生成报告作为证据保存到仓库外。划分依据是实际用途，不能依据文件扩展名认定材料可以删除。
